# 室内二维建图操作说明

这一阶段的目标是用实车 `/scan + /odom` 生成并保存第一张可复现的二维地图。
它同时验证底盘里程计、雷达方向、TF、SLAM参数、USB稳定性和电脑算力，不包含
Nav2自主运动。

## 1. 一次性安装和编译

```bash
sudo apt-get update
sudo apt-get install -y ros-humble-slam-toolbox ros-humble-nav2-map-server

source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
colcon build --symlink-install --packages-up-to spore_patrol_slam
source install/setup.bash
```

工作区固定在 Ubuntu ext4 分区的 `~/spore_patrol_ws`。不要从
`/media/brown/新加卷*` 下的旧副本启动，以免混用两套安装空间。

## 2. 建图前检查

电脑保持接电源，底盘和雷达使用两个已经验证的数据USB接口：

```bash
ls -l /dev/ttyACM0 /dev/ttyUSB0 /dev/ydlidar
ros2 topic info /cmd_vel --verbose
```

若已有底盘、雷达、键盘遥控或Nav2进程，先正常停止，避免重复占用串口或多个
`/cmd_vel` 发布者。落地运动必须有人跟车并能立即断开电机使能或总电源。

## 3. 一条命令启动底盘、雷达、SLAM和RViz

终端一：

```bash
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash

ros2 launch spore_patrol_slam mapping.launch.py \
  base_port:=/dev/ttyACM0 \
  lidar_port:=/dev/ydlidar \
  rviz:=true
```

启动后的TF链应为：

```text
map -> odom -> base_footprint -> base_link -> laser_link
```

RViz刚启动的前几秒可能提示 `map` 不存在；SLAM收到第一帧可用雷达和里程计后
应自动恢复。另开终端检查：

```bash
ros2 topic hz /scan
ros2 topic hz /odom
ros2 topic hz /map
ros2 run tf2_ros tf2_echo map base_footprint
```

预期 `/scan` 约12 Hz、`/odom` 约20 Hz、`/map` 每约2秒更新一次。

## 4. 先录包，再移动

终端二：

```bash
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash
tests/slam/record_mapping_bag.sh
```

录包开始后让小车静止约10秒。终端三以低速启动键盘遥控：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -p speed:=0.08 \
  -p turn:=0.20
```

推荐路线：

1. 从有明显墙角或箱体的位置开始；
2. 以约0.08 m/s沿房间或走廊边缘行驶；
3. 转弯使用连续小角速度，不要快速原地甩尾；
4. 尽量让雷达反复看到已经建过的墙角；
5. 绕一圈回到起点，原地静止10秒等待闭环优化。

避免人群围着雷达移动、镜面玻璃、大面积空旷区域和轮胎打滑。首轮路线控制在
3～5分钟，先验证链路，不追求大范围地图。

## 5. 保存地图和位姿图

保持建图程序运行，在终端四执行：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
tools/save_slam_map.sh indoor_01
```

正常会生成：

```text
maps/indoor_01.yaml
maps/indoor_01.pgm
maps/indoor_01.posegraph
maps/indoor_01.data
```

`.yaml + .pgm` 用于后续Nav2静态地图，`.posegraph + .data` 用于继续建图或
SLAM Toolbox定位。脚本拒绝覆盖同名地图；重测时使用 `indoor_02` 等新名称。

地图保存完成后，先在录包终端按一次 `Ctrl+C`，等待 rosbag2 正常退出；再停止
遥控和建图终端。

## 6. 第一张地图验收

- 墙面应是单层清晰轮廓，而不是多条平行重影；
- 小车回到起点后，起点附近墙角应能重新对齐；
- 地图不能随小车原地旋转而整体扭曲；
- `/scan`、`/odom` 和USB连接全程不中断；
- 终端不能持续刷 checksum、TF或scan matching错误；
- 保存的PGM、YAML、posegraph和rosbag都能找到。

若直线墙出现双层，优先检查轮式里程计尺度、雷达支架晃动和USB丢帧；若转弯后
地图扭曲，优先复测原地旋转角度和雷达yaw；若空旷区域漂移，缩小测试范围并增加
纸箱、墙角等几何特征。

第一张室内地图通过后，再进行重复建图对比、SLAM参数微调和Nav2定位/规划，不要
直接开始无人自主运行。
